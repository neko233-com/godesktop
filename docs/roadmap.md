# 路线图

目标：让 Go 成为构建原生、高性能 Windows / macOS 桌面应用的可行选择。参考 GPUI 的能力方向，按可验证的阶段推进；不作完成日期或性能倍数承诺。

## 已有原型

- [x] Go 1.27 模块、公开仓库、MIT 许可证。
- [x] Go 声明式元素、线性布局、状态调度与事件回调。
- [x] Windows Win32 / Direct3D 12 / DirectWrite 后端。
- [x] macOS AppKit / Metal / CoreText 后端。
- [x] 计数器示例、Go 核心测试、race 检查、原生 smoke 工作流。
- [x] gocode 独立公开 submodule、原生编辑器工作区、基础字符编辑、本地 VSIX 命令宿主。

原生后端已实现，不代表所有硬件、字体、输入法和系统版本均经过验证。CI 的成功状态以 Actions 当前结果为准。

## 下一阶段：可用的应用基础

- [ ] Entity / View 的类型安全状态与订阅，明确生命周期和取消语义。
- [ ] 文本输入、选区、光标、IME、平台剪贴板。
- [ ] 滚动容器、鼠标滚轮、焦点范围与快捷键 actions。
- [ ] 多窗口、最小尺寸、关闭回调、系统菜单。
- [x] 平台字体选择、自定义标题栏、矢量图标、Unicode/滚轮输入事件。
- [ ] 图片、SVG、可控字体回退、文本换行。
- [ ] Windows UI Automation 与 macOS Accessibility。
- [ ] 系统主题、辅助功能设置和 reduced motion。

验收：同一套 Go 示例在 Windows 与两种 Mac 架构上完成相同交互；文本输入覆盖中文 IME、组合字符、emoji 和双向文本。

## 渲染与大型场景

- [x] Metal 三缓冲异步提交环，移除每帧同步等待；原生压力场景检查完成计数、缓冲复用和合批。
- [x] 统一 80 字节 GPU 实例、Metal 顶点生成、着色器裁剪与相邻纹理批次；文本缓存增加字节限制。
- [x] Windows Direct3D 12 显式队列、flip model swapchain、三帧 fence 和自定义 HLSL 绘制。
- [x] 两平台共享字形图集，按 glyph/font/size/scale 缓存；变化文本、淘汰与实际 GPU Unicode 像素验收。
- [x] Windows 设备丢失后保留窗口并重建 GPU 资源，实际 RemoveDevice 的硬件/WARP 回归。
- [ ] 明确的帧调度与动画时钟、增量失效、布局缓存。
- [ ] 虚拟列表与编辑器布局接口。
- [ ] 设备丢失、内存压力、显示器迁移与长时运行测试。
- [x] Metal 原生压力场景输出 CPU 编码 P50/P95、实例数、上传量和真实 GPU 完成计数。
- [ ] 公开启动耗时、空闲 CPU、内存、完整帧耗时与输入延迟，并进行 GPUI 同机对比。

验收：统一硬件、窗口尺寸、字体、数据量和交互脚本；分别测量 1k/10k 行列表、文本编辑、实时更新和窗口缩放。只有在这些场景跑通后才与 GPUI、Fyne、Gio 等框架作可复现对比。

## 分发与稳定性

- [ ] Windows 图标、清单、安装包与代码签名说明。
- [ ] macOS `.app`、Universal Binary、签名与公证。
- [ ] API 兼容策略、版本发布与迁移文档。
- [ ] 完整应用示例、视觉回归与真实设备测试矩阵。

完整替代 Rust + GPUI 需要上述输入、渲染、无障碍和工程能力；首版只建立可运行、可扩展的原生基础。
